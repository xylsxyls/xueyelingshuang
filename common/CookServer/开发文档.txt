一、工程结构与边界

1. src/CookServer/CookServer 是 Windows C++11 HTTP 服务端工程。CookServer 负责生命周期；Config 解析 CookServer.ini；CookHttpServer/CookHttpApiHandler 处理网络和 HTTP；CookApiService 做鉴权、参数解析、路由及结果序列化；AccountStore 管理账号、菜谱关系和社区状态；CookRecipeConfig 解析与校验菜谱；CookSchedule 仅处理排程算法；CookStorageService/CookStorageSyncTask 负责 Redis/MySQL 快照读写和异步同步；CookVideoUploadService 管理分块上传会话；CookVideoSegmentService 用 FFmpeg 对已授权媒体做时间片重封装；CookVoiceService 管理语音任务。

2. src/CookServerTest/CookServerTest 是独立 HTTP 黑盒测试工程，通过配置中的 host、port、超时和最大响应字节数访问服务。测试报告由 CookServerTestReport 写到测试程序目录。测试可以创建账号、钱包记录、评论、菜谱和视频，因此只可指向一次性或隔离测试数据。

3. src/CookWx 是微信小程序前端工程。页面只组织界面与用户操作；utils/api.js 管理 token、请求并发、优先级、失效回调和重试；utils/videoUpload.js 读文件块并顺序上传；utils/videoSegmentCache.js 下载、持久索引、去重、pin 和 LRU；components/cachedVideoPlayer 管理解码器、播放时钟、分段切换和预取；utils/videoLocalPreview.js 默认以原生 video 播放本地片段；utils/videoFrameRenderer.js 仅为可配置诊断路径渲染 I420/RGBA 帧。微信小程序不是 C++ 工程，不能链接 src 下的二次开发库。

二、身份、状态与接口约定

受保护请求由 Authorization Bearer token 找到 userId；HTTP 请求体中的 userId 不作为身份依据。认证失败返回 401。API 的业务错误一般用 JSON `{ "ok": false, "message": "..." }`；媒体字节响应另用 HTTP 状态和响应头。POST 默认不自动重试，避免 toggle、创建、发布等操作因响应丢失而重复执行；只对具有服务端幂等保障的具体调用显式开启重试。

AccountStore 以互斥锁保护当前进程业务快照。持久化使用 CookStorageService：Redis 缓存快照，MySQL 保存 cook_state_snapshot 并通过版本号避免旧异步任务覆盖新版本。该结构是兼容性快照层，不等于拆分后的领域表。配置存储不可用或首次加载失败的处理要结合启动日志和当前配置确认，不可把旧 EXE 的运行表现归于新源码。

HTTP 主要路由包括：
- `/api/auth/register`、`/api/auth/login`、`/api/auth/session`、`/api/auth/logout`。
- `/api/recipes`、`/api/recipes/detail`、`/api/recipes/join`、`/api/recipes/purchase`、`/api/recipes/menu/remove`、`/api/recipes/custom/save`、`/api/recipes/custom/publish`。
- `/api/recipes/personalization/detail`、`save`、`reset`、`sync-times`。
- `/api/plan/preview`、`/api/plan/start`，以及做菜结果与历史接口。
- `/api/wallet/checkin`、`/api/wallet/ad/start`、`/api/wallet/ad/finish`；没有面向正式客户端的任意充值路由。
- `/api/feed`、`/api/feed/watch`、`/api/videos/file`、`/api/videos/poster`、`/api/videos/segment`、`/api/videos/publish`。
- `/api/videos/upload/start`、`/api/videos/upload/chunk`、`/api/videos/upload/complete`、`/api/videos/upload/cancel`。
- 评论、点赞、收藏、关注、消息及语音相关接口。

菜单归属、可制作权限和购买记录分别表达。GET /api/recipes默认只返回已加入菜单；scope=catalog用于发布、个性化及个人资产的可见目录，不自动加入。POST /api/recipes/join只加入菜单，不扣钱、不授予付费菜制作权限；purchase才校验余额及扣款，购买幂等键按账号/菜谱/操作隔离。系统默认只加入免费菜；旧快照迁移时清理误授予的系统付费菜拥有关系，保留真实购买。MENU快照行记录有序菜谱ID与移除集合，旧USER行继续读取。最近加入或打开已加入菜谱详情置顶；未加入的公开详情不自动加入。购买菜不能移出，其他菜移除幂等；免费系统菜的移除记录阻止刷新自动补回。
AccountStoreMenu.cpp集中菜单归属和媒体解析，AccountStoreSocial.cpp集中公开资料、粉丝及双向私信读取，CookApiServiceSocial.cpp集中相关HTTP序列化。共享状态仍由AccountStore互斥锁保护。recipeSummary/recipeToJson输出inMenu、purchased、menuPosition、coverImageId/coverImageUrl、videoId/videoUrl/posterUrl，删除coverColor。原视频优先作者本人作品；没有正方形图时用真实视频poster。utils/recipeAssets集中相对URL补全、封面优先级、五类归一及购买/移除权限，menuActions集中确认和操作，socialActions集中公开主页和取消关注确认。

底部菜单连续展示荤菜、小荤、蔬菜、汤饮、主食，按组保留服务端最近顺序；分类点击使用scroll-into-view，滚动根据分组实测位置联动，只在选中项变化时setData。分组位置在数据变化后测量，不逐帧扫描DOM。未加入菜不出现在菜单；付费已加入未买显示买字，确认后调用purchase。我的菜单排除系统免费菜，其余按menuPosition排序，购买显示已拥有，免费用户菜显示免费菜谱及移出确认。搜索只在当前菜单中执行，移除会清掉本顿选择。recipe-heading-row使用不换行flex，名称flex:1/min-width:0/省略，右侧价格flex-shrink:0/white-space:nowrap，避免旧display:block将状态挤到下一行。
选菜菜单的所有详情路由携带selection=meal；recipe页保存mealSelection并从App选择集合派生selectedForMeal，进入、返回和详情加载后重新读取。此上下文按钮以selectedForMeal决定文案/禁用，点击调用utils/mealSelection，只有已购买或免费菜可添加；不请求长期菜单join/purchase。mealSelection以selectedRecipeIds为权威，selectedRecipes为展示数据，添加/替换去重、保留其他菜并在集合变化时清掉lastPreview缓存。菜单“＋/－”提交同一选择集合，返回onShow重新取选择并预览。悬浮框展开列表每行的chosen-remove减号通过data-id/catchtap复用removeRecipe，不另建选择状态、不调用长期移出接口；名称可收缩省略，用时和按钮不收缩，避免长名称挤掉减号。删除后刷新菜卡/共享选择并按剩余ID预览；清空时沿用schedulePreview空集合分支关闭列表/悬浮框、清除计划与时间块，旧请求按代次及选择集合失效。其他详情入口默认长期菜单语义，按服务端inMenu显示；加入请求使旧详情读取失效，隐藏/换菜后的响应不能误将新页面置为已加入。

“我的菜单”排除官方免费和本人免费创作，后者保留创作区；购买与移出优先取资产recipeId，避免把recipe_界面行编号发送服务端。“我的”固定喜欢、收藏、创作、菜单、个性化五项，无分区计数或横向拖动，删除旧统计与底部退出。头像区域显示自己的获赞/粉丝及查看，退出在账户说明右侧；钱包元宝左、金币次之，签到/广告在右侧竖排。utils/mineMediaAssets转换媒体列表；liked/collection/created模式含义不变，按videoId去重并保留不同视频，创作仅本人已发布。喜欢/收藏三列3:4竖版封面、4rpx间隔、aspectFill和lazy-load；本人创作/菜谱库/个性化使用正方形用户图或poster，不再用纯色模拟封面。MINE_MEDIA_PAGE_SIZE默认24、范围3至60，excludeIds分页，无进展停止；页/分区/ID/URL隔离旧响应和封面错误。列表不预取视频片段。

GET /api/videos/detail返回与首页同一序列化器的完整公开视频元数据，图片不能作为原视频。所有菜单/媒体入口进入现有cached-video-player，右侧头像/点赞/评论/收藏和底部作者/菜名/介绍/查看菜谱/加入菜单均保留，顶部只有返回。刷新社交信息不重复替换解码器源，继续复用既有分段缓存。
GET /api/users/profile只输出userId、nickname、avatarUrl、introduction、following、friend、receivedLikeCount和followerCount；不输出钱包、账号凭据或私人资产。GET /api/users/feed仅允许created/liked，默认18条、上限30，excludeIds分页；视频动作字段按访问者身份计算。GET /api/users/fans只允许本人，默认30、上限60、userId游标；公开主页只有创作/喜欢，关注为长条按钮、取消需确认。新增profile/fans页面按可见生命周期隔离请求。
GET /api/messages/conversation只读当前账号与指定用户的双向chat，单页最多60条，beforeId读取更早内容；POST /api/messages/read只修改当前用户收到的该会话消息。发送需关注；互关即好友，取消任何一侧立即更新关系。消息列表按会话合并，后端按当前关系输出friend/muted，单向未读灰色、互关红色，均不自动弹提醒。conversation页仅可见时每15秒轮询，隐藏取消后续计时并隔离旧响应；发送成功使旧轮询失效，隐藏再返回的旧发送不能覆盖新草稿，读取后更新已读。

简介接口POST /api/users/profile/update仅使用token所属账号；可选userId必须为本人。introduction必须为字符串、合法UTF-8、至多20字且不含控制字符，空串重置默认展示。返回publicProfile字段白名单，失败不改旧值/钱包。AccountStore以稳定userId作为资料/关注/点赞/菜单/个性化归属，支持继续注册用户；只自动创建资源系统账号，不自动虚构creator_demo。系统昵称先从公开资料确定再序列化feed，解决首次首页与详情头像缩写不同。点赞响应增加真实likes总数。

头像与身份升级实现
pages/avatarCrop是独立裁剪页，utils/avatarCrop只计算CSS坐标与8种照片方向变换，utils/avatarMedia负责有界读图、缩小、Canvas导出和清理。使用2D Canvas只绘制一次预览；拖动只移动选框及遮罩，按16ms合并setData，导出时将当前CSS方形映射至512×512。来源不超过10MiB/16MP，超过2048长边先缩小再解码；JPEG质量0.82、输出最多512KiB，可在utils/config调整。相册/拍照由chooseMedia选择；裁剪框可移动、角点缩放、双指缩放；导出Canvas使用自身Image节点。页面存活、请求代次及userId一起拒绝过期回调；换图取消或失败保留原选择；页面卸载及重新选图只删本次压缩结果，不删用户原图。
CookApiServiceAvatar处理POST /api/users/avatar/upload（二进制Content-Type application/octet-stream，Bearer认证，可选userId只能为本人）和GET /api/users/avatar?userId=...&key=...（公开字节）。CookAvatarHelper生成32位十六进制文件键，校验PNG/JPEG真实格式、正方形与最大1024边长、512KiB，再将独有.part原子改名；文件位于EXE同级data/avatars。AccountStoreAvatar同步写Redis和MySQL头像引用，持久化失败恢复旧值并删除新文件，成功后删除旧文件；GET只接受当前账户所引用的键，拒绝任意路径或旧键，返回正确MIME及版本缓存头。照片不塞进全量数据库快照，数据库只存头像引用；data/avatars必须与数据库一起保留和备份。
AccountStoreIdentity在HTTP启动前加载并迁移，qmzdc是登录名及内部userId，昵称全民做大厨；旧system账户、作者、视频、关注集合、私信、会话、奖励、评论、头像URL、个性化键、分享及幂等键完整改为qmzdc。旧数据的余额、购买/菜单/收藏/点赞/观看关系保留。现有xylsxyls保留原内部ID并设admin，qmzdc设super_admin，旧缺字段普通账号迁为user；USER快照在末尾追加role，历史字段位置不变，新注册只写user而不采用请求中的role。初次将无密码系统账户配置为指定加盐PBKDF2凭据，重复启动不重置密码或昵称；只分类，不增加管理权限分支。账号名/内部ID/个性化键冲突或快照读取及同步写入失败拒绝开放HTTP；迁移失败回滚完整内存状态。单进程全量快照及同步迁移所需内存仍受既有模型限制，高并发及大型数据集未验证。
所有7份内置JSON及C++兜底统一归qmzdc；资源视频属于同一账号。系统账号发布的新免费菜按默认系统免费菜单规则同步，付费新菜必须主动加入/购买。

三、菜谱解析与排程

CookRecipeConfig 读取 schemaVersion 1.0 的单菜 JSON，检查 ID、标题、步骤、重复 ID、缺失依赖和依赖环。个人新增步骤与基础步骤在排程前合并；CookSchedule 使用依赖完成时间、共享资源可用时间和前台操作时间安排步骤。若仍存在无法排程的节点，PlanResult.m_errorMessage 带出错误，清空部分时间线，序列化器返回 ok=false。

PlanResult 拥有临时 Recipe 副本时，其拷贝赋值必须同步修正 m_recipes 指针。排程代码不访问 HTTP、数据库、文件、token 或小程序状态。服务端 serializer 同时产生完整计划、摘要计划和可选时间块；失败结果不可被标记为成功。

个性化的后台等待模式最终按安全等级校验：attention/danger 不允许 free，服务端解析、运行时排程和小程序运行时均再次降级为 watch。运行时提前完成、跳过或加时后，客户端重算总时长、动手时间、freeBlocks、freeSeconds 和 edge/watch 汇总；移动受影响任务后重新修复依赖、资源和前台串行冲突。

CookPersonalizationFlow独立处理personalization.taskOrder：包含原始与新增全部步骤ID；原步骤相对顺序不改变。连续新增段继承下一原步骤的依赖并等待上一原步骤完成，再将下一原步骤连到新增段末尾；尾插等待前一步。提交图和插入后图都校验未知依赖/循环，禁用原步骤时穿透到有效先决条件。最多256步；验证失败不覆盖配置。快照新增taskOrder，旧快照缺字段沿用历史追加路径；同步实际用时保留顺序。

四、视频上传与分段播放

1. 上传
客户端声明文件名、类型和长度后创建 session；服务端只从扩展名白名单选择保存扩展名，上传 ID 由 UUID 产生，路径由服务端生成。每块最大 512 KiB；偏移必须连续。已经写入的同一块只有逐字节相同才允许重试。session 绑定登录用户，空闲一小时清除，每用户最多两个，进程最多 64 个。服务重启后首次上传会清理上传目录顶层遗留的 `.part` 文件。完成时核实长度并原子改名，再由 AccountStore 核实文件位于服务端媒体目录、大小和扩展名匹配后登记。发布必须引用该账号真实登记的文件。

2. 服务端片段
`GET /api/videos/segment` 先经 getVideoFile 校验媒体访问权，参数为 videoId、startSeconds、durationSeconds。Config 限制单次时长和输出大小。CookVideoSegmentService 按视频流向前 seek 到关键帧，复制音视频流包并重新封装为 MP4，不做手机侧软件解码；`.meta` 保存片段实际起点和源媒体时长。缓存键包含视频 ID、媒体版本、文件长度、最后修改时间、请求起点和长度，避免服务端把已修改文件映射到旧分段。输出受大小限制，出错会删除临时文件。

当前分段重封装仅在 Windows 编译路径实现；其他平台明确返回不支持。服务端通过 HTTP 响应体返回完整分段，内存占用约受并发请求数乘以单片段上限影响。`VideoSegmentMaxBytes` 默认 50331648 字节，最大配置值 512 MiB；这只是单响应上限，不是服务端磁盘缓存总配额。服务端分段缓存需要后续补充总容量、过期与并发读取安全的回收策略，部署前需监控 `data/videos/segments` 空间。

3. 小程序缓存与播放器
`VIDEO_CACHE_INITIAL_SECONDS=3`、`VIDEO_CACHE_INITIAL_PREFETCH_AT_SECONDS=1`、`VIDEO_CACHE_NEXT_SECONDS=5`、`VIDEO_CACHE_PREFETCH_LEAD_SECONDS=2` 定义首段和后续预取规则。缓存身份包括视频ID、含版本的URL、请求起点和长度。videoDownloadQueue.js合并同片段任务，读者各有代次有效条件；新读者登记后再剔除过期读者，避免同片段被相互取消。VIDEO_CACHE_DOWNLOAD_CONCURRENCY默认1、范围1至2；VIDEO_CACHE_DOWNLOAD_START_DELAY_MS默认150、范围0至1000毫秒，缓存命中不等待。前台请求优先，排队过期任务不发HTTP，运行中过期任务abort，待其回调及文件清理后释放名额。预取每代次同目标只提交一次。
videoSegmentDownload.js向wx.downloadFile传入filePath，直接写USER_DATA_PATH/cook-video-cache/片段键.mp4.part；成功响应应为filePath而非tempFilePath。从onHeadersReceived取时间元数据，校验HTTP200、大小、源时长和实际起点，再rename成.mp4、复核大小并提交索引。超限进度中止下载，取消/失败删除本次暂存，不调用copyFile/saveFile；移动不复制媒体内容。持久索引仍用原storage键，可复用已有合格缓存。

videoCacheFiles.js独立维护实际磁盘占用与回收队列。首次发起下载前或固定缓存命中时异步校准目录（先给下载临时文件留出空间），每批最多四个stat；权限/读取错误不提交半份清单，下次重试。仅回收本目录中符合内部片段命名的文件，不删除未知文件、其他缓存或用户文件。先清理失去索引的遗留片段，再按lastAccess从旧到新回收；删除成功或确认ENOENT才删除索引和扣减占用，EBUSY/权限失败保留实际占用。扫描期间完成的写入/删除覆盖旧快照，避免并发提交丢失。常规回收使用内存文件清单，不逐帧扫目录或同步删除整批文件。

videoSegmentCache.js在下载前串行准入，共用容量预留；VIDEO_CACHE_DOWNLOAD_RESERVE_BYTES默认4MiB，用于提前腾出下载空间，完成后按真实大小调整并再次回收，未通过容量校验不得提交索引。默认总预算VIDEO_CACHE_MAX_BYTES=100MiB、最低10MiB，单段VIDEO_CACHE_MAX_SEGMENT_BYTES=48MiB、最低1MiB。下载途中实际字节量可能大于初始预留，但受单段上限和下载并发限制；100MiB指缓存准入预算，不能据此证明下载瞬时磁盘占用始终低于该值。统计包括本目录未知文件、暂存和预留；固定片段、交接片段、pending目标和写入目标不可淘汰。getAt(...,true,wanted)在固定前核对读者仍有效；取消释放借用引用，采用后由stopDecoder实际停止后释放。删除失败仍计账并要求重新校准；空间不足有界失败，不覆盖正在播放文件。

定位开始即停止旧解码与时钟；新片段就绪前保留旧暂停画面。模拟器移除initial-time定位依赖，在loadedmetadata后显式VideoContext.seek/play；部分原生节点需先play才加载元数据，启动时新节点透明且静音，定位确认后才显示并恢复声音。最多保留一个已就绪旧节点和一个加载中新节点，确认后删除旧节点；加载中暂停只保留已确认的旧画面，避免保留透明节点导致黑屏。就绪要求真实时间位于目标前0.05秒至后0.5秒，提前/大幅越过目标的事件无效。旧代次事件不推进时间，已就绪后忽略时间倒退；失败状态拒绝晚到的元数据、播放和时间事件。seekcomplete携带generation/requestedPosition及实际position；首页据目标、视频及代次匹配，删除1200毫秒兜底播放，延迟恢复也核对代次。页面隐藏时的play、seek和晚到就绪不能重新启动；原生错误停止预取并剔除过期下载。VIDEO_SEEK_END_MARGIN_SECONDS默认0.2秒，拖到终点读取最后可播放帧，播放结束保留最后画面；独立页暂停/播放回调避免重复setData。相邻切段仍可能等待，本次不声称无缝播放。
