Cook 做菜软件需求文档
版本：1.12
更新日期：2026-10-10
范围：CookServer 服务端、CookServerTest 测试工程、CookWx 微信小程序客户端。

一、产品目标

Cook 为用户提供菜谱选择、时间排程、做菜指导、视频浏览和厨友互动。CookWx 使用 JavaScript、WXML、WXSS 和微信小程序基础库；CookServer 提供账号、菜谱、排程、社区和媒体接口；CookServerTest 通过 HTTP 验证服务端接口。Quant 与本产品无关。

第一期以可运行的单机 Windows 服务为目标。菜谱、账号和社区数据由服务端管理；客户端不信任请求中自行填写的 userId，也不把本机文件路径当作已经上传的视频。手机侧控制解码、缓存、并发和预取量，避免连续下载整个视频造成等待和流量浪费。

二、用户与主要流程

1. 账号与登录
用户使用账号和密码注册、登录、退出，并用服务端签发的 token 访问需要登录的接口。token 失效后要求重新登录。服务端以 token 确定用户身份；忽略客户端伪造的 userId。账号状态包括昵称、头像、金币、元宝、菜谱拥有关系、收藏、点赞、关注、个性化设置和已看视频。

本人在“我的”点击头像，从相册或拍照选择图片后进入独立头像裁剪页。裁剪框始终为正方形，可在图片内移动、通过角点或双指放大缩小，不能越出图片；确认后仅上传裁剪结果。输出512×512 JPEG，单图最多512 KiB；取消不替换头像，失败保留原头像并允许重试。图片文件保存在服务器，账号头像引用持久化到数据库；首页视频、本人页、公开主页和粉丝列表使用同一引用，更新后地址带新版本，避免旧图片缓存。
系统账号的登录名为qmzdc，密码使用用户本轮指定值，仍以加盐PBKDF2散列存储。内部userId也为qmzdc；首次升级将旧system及其作品、互动、头像、会话、个性化和余额引用一致迁移至qmzdc；昵称为全民做大厨，昵称允许重复、登录名不允许重复。首次升级将原无密码兼容账号迁移为可登录账号，后续启动不能重置账号。所有随包菜谱与资源视频归该账号，登录后可继续发布新菜谱和视频；系统账号发布的免费菜仍按系统免费菜规则进入用户菜单，付费菜必须主动加入和购买。账号预设三类：qmzdc为super_admin（超级管理员），现有xylsxyls为admin（管理员），后续新注册账户为user（普通账户）；当前只持久化类别，不引入额外权限差异。qmzdc若已被其他userId占用，升级明确失败，不能挪用其他用户身份或数据。

2. 菜谱、菜单和购买
菜单归属与购买权限分开。系统免费菜谱默认加入底部选菜菜单；系统付费菜及其他用户菜谱必须由用户点击“加入菜单”后出现，未加入的黑椒牛柳等付费菜不能自行出现。付费菜加入不扣款、不授予制作权限；加入后在底部菜单及“我的→菜谱库”出现“买”，点击先询问是否购买，确认后由服务端核对余额并扣款，幂等重复购买不能重复扣款。未发布草稿只对作者可见，不能加入菜单或排程。
“我的→菜谱库”不显示官方免费菜谱；购买的显示“已拥有”，其他用户免费提供且已加入的显示“免费菜谱”，已加入但未购买的付费菜以“买”操作表示。免费菜谱提供“移出菜单”，确认后同步从两个菜单移除，取消不改变；已购买菜谱不提供移出操作。新增加入和打开已加入菜谱详情都置顶，两个详情入口共用服务端顺序；浏览未加入菜谱不能自动加入。菜单顺序持久化，系统免费菜移除记录不会因刷新或重启被补回。
底部菜单删除最喜欢、购买区、创作区，只按“荤菜、小荤、蔬菜、汤饮、主食”依次分组；右侧完整列表连续滚动，左侧分类与当前滚动分组联动，点击分类滚到该组。左右列表在固定视口内独立滚动；五类可全部显示时左侧不自动滚动，只切换选中。未来分类溢出时仅最小移动确保当前类可见。右侧按做菜浮栏实际高度保留尾部空白，最末菜完整描述可滚到浮栏上方。“开始做菜”文字在按钮内水平和垂直居中。搜索在全部菜单中筛选，不把未加入菜谱混入结果。菜名与免费菜谱、已拥有或金币/元宝价格同排，状态在右侧，不另占一行；窄屏优先保留完整状态，长菜名省略。
所有菜谱列表使用正方形小封面，优先用户上传的正方形图片，缺少时使用对应公开视频缩略图；不再用纯色块模拟缩略图。详情顶部使用保持原高度的长方形图片，中间透明播放三角，下半段渐变到页面背景色；名称、作者、介绍在图片下方，点击播放进入完整视频页。底部只保留等宽居中的“个性化”和“加入菜单”。从底部选菜菜单进入详情时，该按钮加入本次做菜列表，与选菜页“＋”同步；未选中可加入，点击后不可点并显示已加入菜单，返回选菜页参与预览，减去后再进入可重新加入。点菜页底部悬浮框展开后，每道本次已选菜右侧有减号；点击立即移出本次列表，同步菜品加减按钮并重新计算剩余菜的预计用时，保留长期菜单归属。删完所有菜时收起展开列表及悬浮框，清除旧计划；连续删除时旧预览响应不得恢复已删菜或旧摘要。详情浏览本身不选菜，重复点击不重复加入，未购买的付费菜不能加入本次做菜列表。从首页视频、菜谱库等其他入口进入时，该按钮仍加入长期菜单，成员状态由服务端返回，不由免费或购买权限推断；加入长期菜单不改变本次选择。所有随包菜谱食材用量以克表达，作者输入同样校验克数，详情说明保留。

系统菜谱从服务端 EXE 同级的 res/recipes 读取。每道菜为 UTF-8 JSON，schemaVersion 当前为 1.0；菜谱 ID、步骤短 ID 必须稳定且不重复。依赖不存在、依赖成环或排程不能完整生成时，服务端返回失败原因，不返回半份成功计划。

3. 做菜排程与指导
用户选择已拥有的菜谱后获得完整计划或轻量预览。排程遵守步骤依赖、灶台等独占资源、前台操作串行和后台等待并行。计划包括总耗时、动手时间、可离厨区间和守候区间。

开始做菜后，客户端显示当前操作、倒计时、后台任务、语音和必要提示。跳过、提前完成、加时和暂停要按步骤安全属性执行；高风险步骤不能显示为可离开厨房。切换到其他应用或锁屏时，客户端恢复计时和步骤状态，不将页面隐藏误当成流程完成。

当前前台步骤右侧为“加10秒”和“完成”；正在计时的后台步骤右侧为“跳过”和“加10秒”。加时直接调整，不打开选择或自定义输入弹窗，底部不重复提供完成当前步骤按钮。未来、已完成和已跳过步骤不可调整，危险或需注意的完成/跳过保留安全确认。后台跳过按本次操作终止任务并重排后续依赖，不受旧菜谱前台专用的manualSkippable默认值阻挡；其他已经运行的后台计时保持原起止。

等待/休息的页面文案与语音使用同一时刻的实际剩余秒数，不扣除估计说话耗时、额外秒数或五秒取整；剩余300秒时两者都表示5分钟。重新播报读取新的剩余秒数，播报期间计时继续推进。

4. 个性化
用户可修改步骤用时、禁用或恢复原步骤、增加自定义步骤、重置个性化，并在排程中查看应用提示。个性化顶部与菜谱详情共用渐变封面和透明播放三角。新增步骤包含标题、说明、前台/后台类型、用时、安全级别、后台等待方式，并选择现有第几步之前/之后；立即插入原流程，连续重编号，新增项右侧可删除，不另设我新增的步骤栏。保存顺序参与下一次实际排程，继承前后步骤的先决条件，保留原步骤依赖和安全信息。合并最多256步，未知/重复/缺失ID、原步骤乱序和循环拒绝；旧配置缺顺序仍兼容。危险或需注意的后台步骤强制为留在厨房守候。

开始排程界面提供本次“同步个性化用时”开关，默认关闭。开启后，已点击开始的流程在主动退出、系统返回确认退出或全部做完时询问是否同步；关闭或从未开始时不询问。单菜与多菜均按所属菜谱分组同步本次实际完成的步骤，包括个性化新增步骤。完成时间由运行时记录；跳过、未来和尚未完成步骤不以计划时长覆盖原设置。取消不写入，网络失败保留快照供重试；没有完成步骤时仅提示没有可同步用时。

同步确认在可见页面且原生退出提醒关闭后显示，不能在onUnload中弹框或导航。退出后先切换页面，再由可见页提示；快照只能用于原流程账号，切换账号不能写入另一用户。

5. 钱包、签到和广告奖励
用户可签到并获取配置奖励；广告奖励必须满足服务端记录的真实等待时间，客户端传入的已等待秒数不能代替服务端计时。正式客户端没有直接增加金币的测试接口。真实支付、退款和提现不属于本版能力。

6. 推荐流和厨友互动
首页支持推荐、关注等流类型及连续加载；可浏览公开视频、作者、封面和关联菜谱，点赞、收藏、关注、评论、查看消息并发送厨友消息。评论和互动目标使用稳定的 videoId/recipeId，服务端统一规范化 ID。普通视频可以不绑定菜谱；没有作者授权的关联菜谱不显示为可跳转教程。

“我的”只保留喜欢、收藏、创作、菜谱库、个性化五个固定等宽、无圆角且文字居中的分区，按下/选中有反馈，不横向拖动，不显示分区数量，删除收藏/关注/好友/已购统计栏和底部退出登录。退出登录保留在本人资料区右侧；钱包元宝在左、金币在中右，最右竖排签到和观看广告，缩短钱包高度。共用账户文案放在用户名右侧；下面显示自我介绍，缺省为开心做大厨。只有本人有修改/保存/取消入口，最多20字，保存到服务器。头像下方显示获赞和粉丝，自己的粉丝文字右侧有“查看”，打开独立粉丝页展示头像、昵称、自我介绍。
喜欢、收藏、创作保持三列3:4媒体封面网格；菜谱库和个性化使用上述正方形封面。喜欢为已点赞视频；收藏合并已收藏视频与已收藏菜谱关联的公开视频，同一videoId仅显示一次；创作为本人已发布视频。无关联视频的收藏不生成虚假的视频卡片。
菜单视频和喜欢/收藏等入口统一显示与首页一致的作者、菜名、介绍、查看菜谱、加入菜单及头像/点赞/评论/收藏操作；顶部没有推荐/精选/关注/好友，左上角提供返回。点击作者头像进入公开主页，只提供“创作”和“喜欢”，不返回或展示其收藏、菜单、个性化和钱包。主页显示获赞、粉丝及长条关注按钮；关注后显示已关注，取消前询问，取消对双方好友关系立即生效。
关注后可发送私信；单向关系的消息免打扰，不播放提醒或显示通知，未读数用灰色；互相关注自动成为好友，未读数用红色。消息详情支持双向历史和阅读后清除未读，客户端及服务端均校验消息所属账号，不能读写其他人的私信。
封面使用服务端缩略图，按需加载图片，不因展示网格下载视频片段。分批请求媒体列表，继续滚动才加载后续项；封面不可用显示占位文案，不生成虚假的封面或反复下载媒体。


所有原视频入口保留首页的原生导航区域与底部五项可跳转导航，不进入全屏；返回沿用做菜计划的原生箭头，不显示返回文字按钮或推荐分区。首页、原视频、本人和作者主页共用头像来源；无头像时均显示昵称首个字，不能在头像内显示整个system等用户名。头像的占位颜色和字形一致；作者主页沿用本人页的左头像、右用户名与账户说明、下方简介/获赞/粉丝布局和等宽方形标签，仅保留创作与喜欢，关注按钮在资料下方，不显示本人编辑、退出和钱包。关注后不显示红加号，点赞状态/总数、收藏和菜单状态读取服务端。返回页面只刷新互动元数据，不重新创建解码源。
7. 视频发布与播放
用户从小程序选择视频后，客户端读取文件内容并按顺序上传二进制分块；服务端生成视频 ID 和保存路径，验证文件大小、格式和归属后才允许发布。发布时菜谱关联为可选项。重复分块只有内容完全一致时才幂等成功；跳号、越界、空分块、超限、过期会话和他人上传会话均失败。

发布视频使用自建画面渲染和小程序逐帧解码接口，不以微信内部 video 播放器作为播放控件。按配置从本地持久缓存读取 MP4 时间片段；已缓存位置拖动后直接从本地解码。未缓存位置只请求覆盖目标时间的一段，随后继续顺序预取。用户的具体预取规则为：
- 从片头开始播放时先请求 3 秒。
- 播放到第 1 秒时请求紧接其后的 5 秒。
- 此后每到当前已缓存范围结束前 2 秒，再请求后续 5 秒，直至媒体结尾。
- 3 秒、1 秒、5 秒、提前量及容量均为配置项，不写死在播放器分支中。

开发者工具未实现VideoDecoder时，允许仅platform=devtools使用本地片段预览控件，以验证页面、缓存和预取；该控件只读取USER_DATA_PATH/cook-video-cache内已经下载的MP4，不接收服务器完整视频地址。Android/iOS仍使用逐帧解码与自建画面渲染。模拟器本地预览不能作为真机解码、声音、音画同步或性能验收。

客户端片段缓存按视频身份与播放源版本区分，持久保存在小程序用户目录，采用 LRU 清理；当前上限 100 MiB，单片段上限 48 MiB。下载直接进入可回收的本工程暂存文件，校验后移动为正式片段，不能复制只读临时文件造成双份占用。启动校准实际文件，清理无索引片段和残留暂存；播放、交接和在途文件保护，删除失败保留占用统计。未命中请求采用可配置短延迟合并连续定位，默认150毫秒；下载并发默认1，排队的过期请求不下载，正在下载的过期请求取消并等待文件清理。相同片段共享任务，不取消仍有读者的下载。微信配额不足时只回收本工程可淘汰片段，最多再下载一次，仍失败明确提示，不能循环重试消耗流量；其他目录及无法确认归属的旧临时文件不自动删除。
新定位立即停止旧播放时钟，完成事件必须属于最新目标。模拟器在真实元数据就绪后显式定位，收到接近目标的真实时间事件才显示画面；拖到终点读取最后可播放帧并保留结束画面。一次只解码当前片段，隐藏或销毁时停止解码和音频资源。帧率上限30 FPS，输出最长边不高于720像素；不支持解码、渲染格式或音频接口时显示失败状态。切段连续性、音画同步和手机长期性能另需真机验收。

服务端提供原视频 Range 读取和按时间生成 MP4 的接口；时间片段最长 10 秒，单片段响应上限默认 48 MiB。分段以视频关键帧开始，因此实际起始时间可能早于请求时间，客户端必须据响应头校正 seek 时间。当前时间片生成实现针对 Windows 服务构建。

8. 语音
服务端按配置使用 Windows SAPI 或外部语音提供方生成语音并缓存结果；小程序按计划预取和播放语音。制作步骤只播步骤名，不播详细解释和预计用时；步骤名最多八个字，优先简洁的具体操作短句，随包全部菜谱同步调整。等待/休息仍保留当前实际剩余时间和必要安全提醒。停止播放、退出页面、切换账号时，旧请求或旧播放回调不能重新开始发声。性别匹配必须避免 male/female 子串误匹配。

Windows SAPI按目标性别和文本语言选择可用声音，支持普通SAPI与Speech_OneCore目录中的中文男女声，检查SetVoice结果；缺少中文男声时明确返回资源缺失原因，不能用女声冒充。下载校验同时接受male_/female_生成的合法缓存键，拒绝路径、非法哈希和错误扩展名。

三、关键验收条件

1. 无 token 或无效 token 不能借 userId 访问或修改其他账号数据。
2. 余额、广告奖励、菜谱拥有关系和视频文件都由服务端核实；接口成功必须对应真实存储或有效文件。
3. 私有草稿不会从详情、加入、菜单或排程接口泄露给其他用户。
4. 任何菜谱排程均完整；依赖错误明确失败，不静默返回部分步骤。
5. 高风险后台等待不能允许离开厨房。
6. CookWx 真机播放不使用原生 video 控件；开发者工具仅允许上述本地片段预览。未缓存 seek 只请求目标时间段，命中本地片段不发媒体网络请求。
7. 缓存、上传、片段和帧率均有明确大小/时间限制，错误和取消路径释放临时文件与解码资源。
8. CookServerTest 对身份、购买幂等、草稿权限、排程、评论、视频上传、Range/分段、异常边界和并发请求提供用例；报告通过才可发布本轮服务端程序。
9. 小程序最终播放体验、媒体声音和设备性能由微信开发者工具及真机验证；源代码静态检查不能代替运行验收。

四、部署信息

默认发布方式是将完整 common/CookServer 目录复制到 Windows 服务器，确认 CookServer.ini、res、依赖 DLL 和数据目录与 CookServer1.0.exe 同级，然后双击 CookServer1.0.exe 启动。正式程序名以 VS 工程 Release 的 TargetName 为准，当前为 CookServer1.0.exe；不额外发布无版本号副本。默认 HTTP 端口为 5207；监听地址、存储连接、媒体目录和功能参数以 CookServer.ini 为准。服务需要的 res/recipes、res/video、libmysql.dll、HiRedis.dll 及实际链接所需运行库不能漏拷。不要只复制 EXE，也不要把测试工程或测试报告混入服务目录。

`data/avatars`保存服务器头像，与数据库同为持久数据；首次升级自动将system关联迁至qmzdc，无需手工修改数据库，账号冲突时停止启动而不覆盖。`data/videos/files` 保存上传视频，`data/videos/segments` 保存服务端 MP4 时间片，`data/accounts` 等路径依配置而定。服务数据属于持久数据，升级时不得删除。当前代码版本与 common 中已有 EXE 不必然相同；仅用本轮成功构建并通过 CookServerTest 的 EXE 替换发布目录程序。正式微信小程序上线还需要受支持的 HTTPS 域名与小程序网络配置；当前开发地址不是生产地址。

Voice.TtsProvider=windows_sapi时，服务器本身必须具备中文男声/女声资源；复制CookServer目录不会安装Windows声音。缺少男声需要安装中文男声资源，或配置支持男女声的外部语音提供方。程序只读取声音目录，不修改注册表。2026-10-09发布物已在本机具备Huihui/Kangkang声音的隔离环境真实验证；远端声音资源及小程序实际听感仍需验收。

五、本版范围边界

方案中还提出菜谱初始定价上限，以及依据播放量/购买量逐步提升作者定价额度；本版没有完整的作者额度模型、管理入口或审核流程。方案提出语音播报期间免手操作的跳过/加时指令；当前语音模块是语音生成和播放，没有语音识别指令闭环，不得显示为已支持。

本版不实现微信 OAuth/统一跨平台账号绑定、真实支付结算、完整后台审核、菜谱不可变版本和购买者版本升级、执行中计划/每一步实际耗时的服务端恢复、数据库拆分迁移工具、对象存储/CDN、分布式高可用和数据库自动备份恢复。当前服务端以 Redis/MySQL 快照承载账号状态，并从 JSON 加载系统菜谱；不应把它描述成已实现完整的菜谱数据库版本管理或生产支付体系。存储失败原子性、服务端片段目录总容量、媒体编码兼容及微信基础库兼容均须按开发/测试文档记录；未运行不得标记通过。
