﻿SplitViewer需求文档
版本：0.9
状态：Windows Release x64图片缩放与原生文件选择修订已发布；其他平台未实测
更新日期：2026-09-24
职责：记录SplitViewer从SplitViewer_old迁移到Qt、Core和Test三工程后的用户可观察行为及验收依据。

一、需求范围

1. 保留旧版SplitViewer的可观察功能
确认：C1已确认；本轮C2至C7免口令，但仍执行对应设计、开发、测试和自查
规则：以src/SplitViewer_old/SplitViewer为行为基线，将旧版Win32/GDI+应用迁移为Qt桌面应用；迁移后的主应用、核心库和测试工程分别归位，不删除或改写旧版基线。界面由AI按旧版功能自行设计为清晰、紧凑的Qt界面，不另等待界面效果确认。
范围：
1) src/SplitViewer：PC端Windows、Linux、macOS的Qt界面、人机交互、绘制、文件对话框、平台适配和启动入口。
2) src/SplitViewerCore：Windows、Linux、macOS、Android、iOS共用的C++11核心模型和业务规则，禁止包含Qt、Windows窗口/GDI/注册表头或其他平台界面代码。
3) src/SplitViewerTest：Qt测试界面、Core行为测试、测试素材和报告入口；测试预期独立于被测实现。
4) common/SplitViewer：正式需求文档、开发文档和最终Release交付物；common/SplitViewer_old保留旧版交付物。
完成：三工程职责边界明确，旧版代码可追溯，Core不依赖Qt或Win32界面能力。

2. 支持目标和构建约束
确认：C1已确认
规则：PC目标为Windows、Linux、macOS；手机目标为Android、iOS。手机界面另行开发，本轮只提供可被手机界面调用的Core能力。Release默认64位、动态库链接；Qt应用和Test的version脚本只准备依赖，不把应用自身当作CloudRebuild库构建；Core的version脚本保留现状，作为Core本体构建入口。本轮正式测试只执行Windows Release x64；Linux/macOS不在当前环境编译，只做源码级跨平台自查，后续具备环境后再实测。
完成：构建方案能区分Core动态库、Qt应用和Qt Test，依赖位数、配置和dll/lib组合一致。

二、用户可观察功能

1. 启动和打开内容
确认：C1已确认
步骤：
1) 不带路径启动时显示按当前桌面分辨率宽高比计算的工作区，舞台宽度和高度分别为桌面宽度和高度的一半，窗口居中，初始只有底部基础层和一个空叶子。
2) 启动参数为普通图片路径时，将图片加载到基础层第一叶子。
3) 启动参数为.sv路径时，恢复配置文件中的基础层、浮动图层、分割树、图片路径、缩放状态、边框、选中图层、窗口位置和工作区宽高比。
4) 命令行参数debug只启用调试日志，不改变用户功能；路径和debug参数可同时出现。
5) 图片或配置不存在、无法读取、格式不支持时保留可用窗口并给出失败反馈，不把失败内容显示为成功。
完成：启动路径的类型判断、加载结果和失败状态可观察，旧版可打开的图片及.sv配置在兼容范围内可迁移。

2. 工作区、分屏树和图层
确认：C1已确认
规则：
基础层覆盖工作区；浮动图层默认位于工作区中部，按创建顺序叠放，后创建图层在上方。每个图层拥有独立的分屏树，节点为叶子或水平/垂直分割节点。
右键叶子节点提供“水平分割”“垂直分割”“删除分屏”。分割时原内容留在第一子叶子，第二子叶子为空；分割比例默认0.5并受最小窗格限制。删除分屏时以同级兄弟替换父节点；根叶子不能删除。
左键空叶子的加号打开图片；左键有图叶子拖动图片；拖动分割线调整比例；按住Ctrl拖动浮动图层内部移动图层；拖动图层边缘调整大小。图层始终限制在工作区内并保持最小宽高。
点击叶子选中其图层；选中浮动图层边框为红色，普通边框为深色；F1切换边框显示。
完成：上述操作只修改对应树、图层和视图状态，不串改其他实例或无关图层；失败、取消和空状态有明确反馈。

3. 图片视图、缩放和导出
确认：C1已确认
规则：
图片叶子支持自动适配、手动缩放和偏移。工作区/窗格尺寸变化时，自动适配视图重新计算比例；手动视图按旧版规则保持比例与偏移关系。鼠标滚轮以指针所在叶子为目标，首次滚轮退出自动适配；普通步长为1.05，按住Ctrl为1.01，缩放范围受适配比例限制。拖动改变偏移，缩放提示显示当前相对适配比例并自动消失。
“另存图片”将基础层和浮动层合成后按当前屏幕可容纳的完整舞台尺寸导出；PNG/JPEG/BMP/TIFF已验证。按用户决定使用Qt自带插件，本机GIF可读但不可编码，保存GIF必须明确反馈失败，不伪造成功。
空叶子显示加号；嵌入窗口叶子显示窗口内容并不再作为图片处理。
完成：同一输入、窗口尺寸和操作顺序产生与旧版一致的布局、缩放、偏移和导出结果；无法自动判断的视觉/质量差异在测试记录为人工项。

4. 配置文件和兼容性
确认：C1已确认
规则：
.sv文件保持PNG容器。当前格式在PNG的IEND前写入svCf自定义chunk，chunk数据为带UTF-16LE BOM的配置内容；旧版尾部“--SPLITVIEWER_CONFIG_UTF16LE--”格式仍可读取。缩略图来自当前工作区，不包含嵌入外部窗口。
配置内容保留旧版Version=2、StageAspect、BorderVisible、SelectedLayer、LayerCount、Window位置、Base/Layer节点树、Kind、Direction、Ratio、First、Second、Path、HasImage、AutoFit、Scale、OffsetX和OffsetY字段语义。不存在的图片路径恢复为空叶子并记录失败。
首次保存使用另存对话框；已有配置再次保存沿用路径。没有任何内容时主按钮为“加载配置”，有内容时为“保存”。
完成：新生成的.sv可被本程序读取；旧版生成的.sv可按上述兼容规则读取；读取失败不破坏当前有效文档。

5. 工具栏、快捷键和关于窗口
确认：C1已确认；C2本轮免口令
规则：工具栏提供保存/加载配置、另存图片、新建图层、全屏和关于入口，并有中文悬浮提示；关于入口显示res/SplitViewer.png资源图标。双击工作区和F11切换全屏，Esc退出全屏；全屏隐藏工具栏并恢复原窗口位置/样式。关于窗口显示“关于分屏看图”和版本1.0信息，并阻止主窗口重复操作。嵌入的原生窗口随所属叶子矩形同步缩放，双击全屏时继续占满原分屏区域。
完成：Qt界面布局和状态反馈覆盖旧版入口；本轮由AI自行完成界面设计和内部核对，人工界面确认不作为阻塞条件。

三、平台边界与待确认项

1. 外部窗口嵌入的跨平台定义
确认：已澄清；C2至C7免口令
规则：旧版支持从Windows外部顶层窗口拖入空叶子、嵌入显示、拖动嵌入窗口到工作区外还原，以及关闭时恢复外部窗口。迁移后该功能只在SplitViewer Qt层实现，按Windows、Linux、macOS分别使用#ifdef隔离底层窗口句柄、鼠标追踪、样式和恢复代码；优先使用Qt WId及现有跨平台接口，缺失部分由Qt工程的平台适配代码补齐。Core不保存或处理窗口句柄，也不包含跨端组合代码。Android/iOS本轮只交付Core。

2. 文件关联和缩略图注册
确认：已澄清；C2至C7免口令
规则：旧版在Windows用户注册表注册.sv打开命令、图标和PNG缩略图处理。迁移后Windows Qt版继续实现；Linux/macOS使用各自平台接口或条件编译实现，当前没有对应环境时至少保证非目标平台代码不因缺少Windows头而无法编译，暂时无法可靠实现的系统注册入口留出平台适配函数并安全降级；移动端由后续宿主接入。

3. 图片格式与第三方解码范围
确认：已澄清；C2至C7免口令
规则：图片解码和编码先使用Qt自带图片插件；Windows Release x64实测当前插件可用范围。缺失格式或透明度差异记录为后续依赖缺口，不在本轮擅自引入独立图像库。

4. 本轮正式测试和发布范围
确认：已澄清；C2至C7免口令
规则：本轮测试只执行Windows Release x64。Linux/macOS不在当前环境编译，完成跨平台头文件、条件编译、路径/类型和依赖方向的源码自查，并在测试文档标记未实测；Core五端实测留待相应环境。本轮正式发布到common/SplitViewer和common/SplitViewerTest；Debug和用户人工完整试运行未执行。

2. 架构和构建一致性
确认：C1已确认

3. 测试证据
确认：C1已确认；C3、C6本轮免口令

五、本轮修正版验收
确认：沿用C1及C2至C7免口令授权；最新用户要求重新核对全部功能
规则：双击后的全屏对象是整个舞台内容，隐藏工具栏和窗口外框，Esc/F11恢复普通或最大化状态；分割后两个子区域使用各自尺寸，每个空叶子都有独立加号；图片必须同时受舞台、图层、叶子裁剪，滚轮放大和平移不得覆盖邻区。
完成：Windows Release x64的71项自动回归及6项Core冒烟通过，详见common/SplitViewerTest/reports/refactor/final-release/ui-results.txt和core-smoke.txt。嵌入视频必须在实际桌面上可见、按分屏客户区等比适配且帧持续变化；双击进出全屏不触发播放器自身全屏或暂停；普通单击仍可暂停和继续，拖出及关闭宿主恢复独立播放器。测试使用真实LumaPlayer和Test生成的动态AVI，独立正式EXE另有同输入像素检查。本轮发布更新EXE及Core DLL，不包含Qt动态库、Qt插件或散装PDB，匹配PDB已用7z极限压缩归档。
边界：自动文件选择用测试适配返回路径，实际鼠标命中、菜单、绘制及读写均执行产品代码。原生文件选择框的人工作业、任意第三方软件跨进程嵌入、资源管理器实际缩略图显示、非Windows平台和长期压力没有据此宣称通过。

六、2026-09-23程序图标补充
SplitViewer1.0.exe在Windows资源管理器中使用固定的专用图标，采用蓝色分屏山景设计并适配多种图标尺寸。通过SplitViewer打开的图片仍使用图片自身的缩略图，不将图片的缩略图处理器改为程序图标。本项为工作流结束后的独立增量需求。

七、2026-09-24图层交互与关于窗口增量
1. 关于按钮打开由DialogManager管理的SplitViewer专用内容窗口，内容区使用浅色卡片QSS、分屏图标、标题/版本信息、功能说明和青蓝色“知道了”按钮；不使用窗口阴影，阴影后续由QtControls统一实现；不修改全局TipDialog。
2. 右键菜单新增“删除图层”。基础层该项置灰；浮动层删除时先解除该层全部叶子的外部窗口，再由Core释放整棵图层树；“删除当前分屏”仍只删除非根叶子。
3. 画布获得焦点且选中浮动图层时，Delete键删除整层；基础层或画布未聚焦时不执行删除。
4. 浮动图层左上角8像素热区使用四向移动光标并支持无Ctrl拖动整层；其余角点和边缘缩放行为保持。
5. 验收用例为176、178—182，先交付lib目录试运行版供人工查看，不进入common正式发布；Core、SplitViewer和SplitViewerTest的Windows Release x64构建已通过。

八、2026-09-24关于窗口视觉方案落地
关于窗口按已确认设计图改为浅色卡片布局：左侧为横竖分屏图标，右侧为产品名与版本号，中间使用细分隔线和居中功能说明，底部为居中的青蓝色圆角“知道了”按钮。窗口参数关闭阴影，保留DialogManager托管和原有关闭回调。当前仅生成lib目录试运行版，等待人工查看后再决定阴影控件接入和正式发布。
九、2026-09-24关于窗口验收修订
1. 关于框左侧必须使用res目录中的SplitViewer.png资源图标，图片仍显示原图缩略图语义；不在界面代码内重新绘制图标。
2. 标题栏“关于分屏看图”显示为18px加粗文字，使用QtControls控件接口设置。
3. 关于框在主画布灰色区域的全局矩形内上下左右居中，正文高度变化时定位规则不变，当前可见内容尺寸保持520x340，外层阴影不改变中心。
4. 无阴影自定义窗口保留1px深色外边框，确保Windows拖动窗口时的黑色目标位置轮廓不被不透明灰色客户区覆盖。

十、2026-09-24关于窗口阴影修订
1. 关于窗口启用QtControls统一阴影，阴影按照已确认视觉方案采用四周均匀的蓝灰色柔和渐变，四个角部连续过渡，不使用厚重的单侧投影。
2. 阴影区域与标题、内容区分离，窗口客户区保持不透明；系统拖动时的黑色目标位置四边框必须完整可见，不能被底部灰色客户区覆盖。
3. 阴影不会改变关于卡片的设计尺寸或居中规则，正文增加时仍以主画布灰色区域上下左右居中。

十一、2026-09-24移动命中与边框复核
1. 阴影不能额外绘制一层同级深色矩形框；可见卡片边框和系统移动外沿各自只保留一层。
2. 阴影预留区域不能缩小可拖动标题栏的命中范围，标题栏的实际客户区位置必须完整返回Windows的HTCAPTION。

十二、2026-09-24图片缩放与文件选择增量
1. 原图按比例缩小时，界面先对大图执行高质量平滑预滤波，再绘制到分屏区域；人物和高对比边缘的锯齿应明显减少，图片比例、裁剪、缩放和平移语义保持不变。
2. SplitViewer生产环境的加载、配置保存和图片导出路径选择使用Qt平台原生QFileDialog，打开仍要求已有文件，保存由系统文件窗口处理覆盖提示；测试自动化保留托管选择器作为仅测试驱动路径。
3. Windows Release x64发布只替换common/SplitViewer/SplitViewer1.0.exe和common/SplitViewerTest/SplitViewerTest1.0.exe；Qt运行库、插件和未变动态库不重复复制。匹配PDB统一压缩存放在common/SplitViewerTest，发布目录和lib不保留散装PDB。
