# ToDesk 加密代理工具说明

这个目录是给 ToDesk 使用的加密代理通道，不是全局 VPN，不会接管整台电脑的网络。它和 Quant 工程没有关系，统一放在 `common/ToDeskTlsProxy`。

当前支持两种模式：

- TCP 模式：Ubuntu 本机 `127.0.0.1:52030` → 本机 HTTP/SOCKS 适配器 → stunnel/mTLS → Windows 服务端 TCP `52030`
- UDP 模式：Ubuntu 本机 `127.0.0.1:52030` → Hysteria 2 → Windows 服务端 UDP `52030`

默认仍然是 TCP。你要测试低延迟 UDP，就显式执行 `start udp`。

只在你被允许使用外部代理或远程访问的网络环境里使用它。

## 针对跳 ping/断连做过的优化

- 本机 Python 适配器的长连接转发阶段不再保留 15/30 秒 socket timeout，避免 ToDesk 某个方向短时间没数据时被本机适配器主动断开。
- 本机 Python 适配器会给 TCP socket 开启 `TCP_NODELAY` 和 `SO_KEEPALIVE`，减少小包等待和长连接僵死。
- TCP/stunnel 客户端和服务端都加入 `TCP_NODELAY`、`SO_KEEPALIVE`。
- UDP/Hysteria 使用 QUIC keepalive，把 BBR profile 调成 `conservative`，并把服务端 UDP idle timeout 提到 180 秒，优先降低抖动和偶发断流。
- Python 适配器默认不再记录每条连接日志，减少 systemd journal 日志 I/O 干扰；需要连接明细时可以手动给服务参数加 `--verbose`。
- Ubuntu 侧长期进程使用 systemd 自动重启，进程异常退出时会自动拉起；执行 `stop` 时不会被重新拉起。

## 文件说明

`common/ToDeskTlsProxy` 里主要文件：

- `vpn_todesk_init.sh`：Ubuntu 初始化脚本，生成证书、生成 Windows 服务端包、安装 Ubuntu 客户端服务。
- `vpn_todesk.sh`：Ubuntu 日常启动/停止/查看状态/查看日志脚本。
- `vpn_todesk_uninit.sh`：Ubuntu 卸载脚本，会停止并删除本工具安装的 systemd 服务和 `/etc/vpn-todesk`。
- `vpn_todesk_server_init.bat`：Windows Server 2012 初始化脚本。
- `vpn_todesk_server.bat`：Windows 服务端日常控制脚本。
- `vpn_todesk_server_uninit.bat`：Windows 服务端卸载脚本。
- `hysteria-linux-amd64`：Ubuntu UDP 模式使用的 Hysteria 2 客户端。
- `hysteria-windows-amd64.exe`：Windows Server UDP 模式使用的 Hysteria 2 服务端程序。
- `nssm.exe`：Windows UDP 模式使用的服务包装器，用来把 Hysteria 注册成 Windows 服务。

## Ubuntu 首次初始化

可以把整个 `ToDeskTlsProxy` 目录拷贝到 Ubuntu 的 home 目录下执行，例如：

```bash
cd ~/ToDeskTlsProxy
chmod +x vpn_todesk_init.sh vpn_todesk.sh vpn_todesk_uninit.sh
./vpn_todesk_init.sh
```

初始化脚本会：

1. 安装 Ubuntu 侧需要的基础包：`stunnel4`、`openssl`、`ca-certificates`、`curl`、`iproute2`、`python3`。
2. 生成或复用 `pki-out/` 里的私有证书。
3. 生成或复用 `pki-out/hysteria-auth.txt` 里的 UDP 强随机密码。
4. 生成 `windows-server-package/`，里面包含 Windows 服务端需要的配置、证书、BAT 脚本和 Hysteria Windows 程序。
5. 暂停并提示你把 `windows-server-package/` 里的全部文件拷贝到 Windows 服务端：

```bat
C:\ProgramData\ToDeskTlsProxy
```

拷贝完成后，在 Windows 服务端按后面的“Windows 首次初始化”操作。Windows 初始化成功后，回到 Ubuntu 这个暂停的窗口按回车，Ubuntu 初始化会继续安装本机服务。

如果 Ubuntu 安装依赖时因为 Chrome、Beyond Compare 等第三方 apt 源缺 GPG key 失败，脚本会打印一组修复命令。你可以按提示手动执行后，重新运行：

```bash
./vpn_todesk_init.sh
```

如果 Windows 服务端已经部署过，只想重装 Ubuntu 客户端，可以用：

```bash
./vpn_todesk_init.sh --client-only
```

## Windows Server 2012 首次初始化

先把 Ubuntu 生成的 `windows-server-package/` 目录里的全部文件拷贝到：

```bat
C:\ProgramData\ToDeskTlsProxy
```

然后在 Windows 服务端打开“管理员身份”的 CMD，执行：

```bat
cd /d C:\ProgramData\ToDeskTlsProxy
vpn_todesk_server_init.bat
```

脚本会检查：

- stunnel 是否已安装。TCP 模式依赖 stunnel；如果没安装，脚本会打印官方下载地址并暂停，等你安装后按回车继续。
- Hysteria Windows 程序是否能运行。UDP 模式的 Hysteria 和 NSSM 都已经放在包里，不需要额外安装。
- 包校验和是否正确。
- Windows 防火墙是否已放行 TCP `52030` 和 UDP `52030`。

脚本还会提示你确认腾讯云安全组已开放：

- TCP `52030`
- UDP `52030`

你说 UDP `52030` 已经开好了，重新部署时只要确认 TCP/UDP 两条规则都在即可。

初始化成功后，Windows 端会同时启动 TCP 和 UDP 服务端能力。TCP 是 Windows 服务 `vpn-todesk-server`，UDP 是由 NSSM 包装的 Windows 服务 `vpn-todesk-server-udp`。
UDP 服务会把 Hysteria 日志写到 `C:\ProgramData\ToDeskTlsProxy\logs\hysteria-server.log`，Hysteria 异常退出时 NSSM 会自动拉起。

## Windows 服务端日常命令

```bat
cd /d C:\ProgramData\ToDeskTlsProxy

vpn_todesk_server.bat start tcp
vpn_todesk_server.bat start udp
vpn_todesk_server.bat start all

vpn_todesk_server.bat stop tcp
vpn_todesk_server.bat stop udp
vpn_todesk_server.bat stop all

vpn_todesk_server.bat status all
vpn_todesk_server.bat logs tcp
vpn_todesk_server.bat logs udp
```

不写模式时默认是 TCP：

```bat
vpn_todesk_server.bat start
vpn_todesk_server.bat stop
vpn_todesk_server.bat status
vpn_todesk_server.bat logs
```

`start tcp` 会启动 TCP 服务并设为开机自启；`stop tcp` 会停止 TCP 服务并取消开机自启。

`start udp` 会启动 UDP/Hysteria 服务并设为开机自启；`stop udp` 会停止 UDP/Hysteria 服务并取消开机自启。

服务端可以 `start all`，因为 TCP `52030` 和 UDP `52030` 是不同协议，不冲突。

## Ubuntu 日常命令

TCP 模式：

```bash
./vpn_todesk.sh start
./vpn_todesk.sh start tcp
./vpn_todesk.sh stop tcp
./vpn_todesk.sh status tcp
./vpn_todesk.sh logs tcp
```

UDP 模式：

```bash
./vpn_todesk.sh start udp
./vpn_todesk.sh stop udp
./vpn_todesk.sh status udp
./vpn_todesk.sh logs udp
```

停止全部：

```bash
./vpn_todesk.sh stop all
```

Ubuntu 本机不能同时 `start tcp` 和 `start udp`，因为两种模式都要监听 ToDesk 填写的同一个本地端口 `127.0.0.1:52030`。启动其中一种模式时，脚本会自动停止另一种模式并切换开机自启状态。

## ToDesk 代理设置

ToDesk 代理界面里填写：

- 地址：`127.0.0.1`
- 端口：`52030`
- 用户名：留空
- 密码：留空

如果 ToDesk 有代理类型选项：

- TCP 模式下，HTTP 或 SOCKS 一般都可以，因为本机有适配器。
- UDP 模式下，Hysteria 客户端同一个端口同时提供 SOCKS5 和 HTTP 代理。

## 重新部署一台新机器

推荐流程：

Ubuntu：

```bash
cd ~/ToDeskTlsProxy
./vpn_todesk_uninit.sh
```

Windows：

```bat
cd /d C:\ProgramData\ToDeskTlsProxy
vpn_todesk_server_uninit.bat
```

然后重新执行完整初始化：

Ubuntu：

```bash
cd ~/ToDeskTlsProxy
./vpn_todesk_init.sh
```

按脚本提示把新的 `windows-server-package/` 拷到 Windows 服务端，再执行：

```bat
cd /d C:\ProgramData\ToDeskTlsProxy
vpn_todesk_server_init.bat
```

Windows 成功后回 Ubuntu 按回车，最后启动 UDP：

```bash
./vpn_todesk.sh start udp
```

## 卸载

Ubuntu 客户端卸载：

```bash
cd ~/ToDeskTlsProxy
./vpn_todesk_uninit.sh
```

它会先停止 TCP/UDP 相关服务；如果服务本来就是停止状态，也会继续卸载。它会删除本工具创建的 systemd 服务和 `/etc/vpn-todesk`，但不会卸载 `stunnel4`、`python3`、`openssl` 等 Ubuntu 软件包，也不会删除当前项目目录、`pki-out/` 或 `windows-server-package/`。

Windows 服务端卸载：

```bat
cd /d C:\ProgramData\ToDeskTlsProxy
vpn_todesk_server_uninit.bat
```

它会停止并删除 `vpn-todesk-server` TCP 服务，停止并删除 `vpn-todesk-server-udp` UDP 服务，删除本项目创建的 Windows 防火墙规则，并删除 `C:\ProgramData\ToDeskTlsProxy`。它不会卸载 stunnel，也不会自动删除腾讯云安全组里的 TCP/UDP `52030` 规则。

## 私钥和证书注意事项

`pki-out/offline-ca/` 里是 CA 私钥，不要拷贝到 Windows，不要提交到代码仓库，不要发邮件，也不要放在共享盘上。

如果删除整个 `pki-out/` 后重新执行初始化脚本，会生成一套新的证书和 UDP 密码。这种情况下 Windows 服务端和 Ubuntu 客户端必须一起重新部署。
