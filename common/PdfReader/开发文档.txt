一、现有工程基线

src/PdfReader_old/PdfReader 是完整 Win32 工程。PdfReaderWindow.cpp/h 集中承担窗口创建、标题栏和工具栏自绘、缩略图/正文绘制、滚动、缩放、拖拽、右键菜单、文件对话框、密码提示、帮助窗口和保存命令。PdfReaderPromptDialog、PdfReaderAboutDialog、PdfReaderButtonToolTip、TopButtonState、PdfReaderHelper 中与 HWND、HDC、RECT、Win32 对话框或路径 API 相关的部分属于界面和平台适配。

旧工程的 PageItem、BitmapCacheEntry 是页面顺序和渲染缓存数据；PdfReaderWindow 还直接拥有 PdfEngine、PdfDocument、文档列表和页面列表。PdfEngine 已在 src/PdfEngine 中提供无 Qt 的 Pdfium 初始化、PDF 打开、页面尺寸、BGRA 渲染、页面导入保存和页码范围解析能力。

迁移开始时三个工程为模板；目前已实现 Qt 产品窗口、共享 Core C/C++ API 和真实窗口回归测试，模板描述仅作为历史基线。

首轮落地后，Core 已以 PdfReaderCore/PdfReaderCoreC 两个实现文件承载 C++ 和 C 边界；PdfReaderCoreAPI.h 按 PDFREADERCORE_USE_C_API 选择声明。PdfReaderCoreBridge 只包含该入口，PdfReaderTest 的 CApiSmoke.c 直接以C编译该入口。

二、代码分类和归属

1. Core 归属

将文档生命周期、文档列表、当前页面顺序、页面来源标识、当前主文件路径、打开/密码重试所需状态、页面尺寸和渲染请求、页面插入和重排、保存当前顺序、另存为、分页保存、页码范围解析以及错误结果放入 PdfReaderCore。Core 只包含 C++11 和跨平台库，不包含 Qt、QWidget、QImage、QString、Qt 事件循环或平台窗口句柄。

页面位图数据使用现有 PdfEngineBitmap 或等价的 Core 数据结构；界面缩放、滚动位置、选中高亮、命中测试、缓存淘汰和绘制矩形属于 PdfReader。Core 的文档和页面对象由 Core 负责释放，保存或渲染期间不允许调用方提前关闭来源文档。

2. PdfReader 归属

将旧 PdfReaderWindow 的 Win32 消息处理改为 Qt Widgets 事件和信号槽：主窗口、标题栏/工具栏、左侧缩略图视图、右侧正文视图、滚动条、Ctrl 加滚轮缩放、缩略图长按拖拽、插入位置提示、右键菜单、打开/保存/文件夹选择、密码输入、帮助和按钮提示均由 PdfReader 实现。Qt 代码只通过 PdfReaderCore API 操作文档和页面，不直接访问 PDFium 或 Core 内部类型。

3. PdfReaderTest 归属

保留 Qt 测试界面，同时增加可独立选择的 Core 用例。用例使用稳定数字 ID、中文名、类型、输入、独立预期、实际结果、超时、取消和报告；重点覆盖打开失败和密码、页面数及尺寸、渲染输出、插入/重排、页码范围、分页保存、另存为、空状态、重复关闭和失败后清理。

4. C/C++ API 和 Qt 对接

PdfReaderCoreAPI.h 是唯一对外包含入口。调用方在首次包含前定义 PDFREADERCORE_USE_C_API，入口随后包含 PdfReaderCoreC.h；未定义时包含 PdfReaderCore.h。Windows 下沿用 API.h 的导入宏和 Debug/Release 自动链接，Linux、macOS、Android 和 iOS 使用已有可见性宏。

PdfReaderCoreC.h 只使用 C 可表达的类型，包含 stdint.h、stddef.h，并在 C++ 编译时用 extern "C" 包住函数声明。句柄是不透明指针；结果和状态使用显式枚举；字符串统一为以零结尾的 UTF-8；位图、页面信息和操作结果使用固定布局结构体，借用数据的有效期写入注释。PdfReaderCoreC.cpp 创建和销毁 C 上下文，内部持有 PdfReaderCore C++ 对象，所有入口检查空参数、捕获异常并转换为 C 结果码；不让 C++ 异常、STL 或 Core 私有对象穿过 C 边界。

PdfReader 的桥接类仿照 src/LumaPlayer/LumaPlayer/LumaPlayerCoreBridge：桥接头先定义 PDFREADERCORE_USE_C_API，再只包含 PdfReaderCoreAPI.h；桥接类拥有 Core 不透明句柄，负责 init/uninit/destroy 顺序、路径和结构体转换、结果读取及QImage缓冲区转换。Qt 窗口、模型和测试代码不直接 include PdfReaderCore.h 或 Core 内部头。PdfReaderTest 另设一个 .c 编译单元，直接定义宏并包含 PdfReaderCoreAPI.h，验证纯 C 头可以独立编译和调用。

Qt 缩略图使用 TopToBottom + wrapping=false 的单列布局。关闭 QListWidget 内部拖放和框选，改为500毫秒长按、源项单选、插入线、滚轮/边缘滚动及明确取消事件；先由 Core 完成移动，再重建视图并选择源页的新位置。缩略图页图使用固定基准尺寸，Ctrl 滚轮只改变灰色条目背景的高度；自定义 delegate 将页图居中绘制，条目整块命中，所以页图周围灰色区域与页图具有相同选择逻辑。选中左侧条目后通过 ensureWidgetVisible 将对应正文页带入右侧视口；正文滚动时按视口内可见面积最大的页面更新当前选择，并确保左侧对应缩略图可见。正文与缩略图独立缩放，仅视口相交页持有位图，离屏即释放。

保存和导出先写同目录唯一临时文件，再由 CSystem::replaceFile 替换；Windows 使用 MoveFileExW(REPLACE_EXISTING|WRITE_THROUGH)，不预先删除目标。主文件覆盖先释放来源句柄，替换后重新打开；失败保留恢复 PDF 并报告路径。CSystem 和 PdfEngine Release 各自使用 MT，因此 FILE 的打开/写入/关闭必须全部回到 CSystem 的同一运行库，不能直接在 PdfEngine 内 fwrite/fclose。

C API 增加 pdfReaderCoreSaveEachPageEx 的明确覆盖参数，原函数默认禁止覆盖；所有目标先查冲突。pdfReaderCoreValidatePageRange 在文件对话框前验证范围，解析仍归 Core/PdfEngine，Qt 不复制解析逻辑。

三、拟定 Core 边界

PdfReaderCore 对外提供初始化/释放、打开和关闭文档、查询页面数量和来源、读取页面尺寸、渲染 BGRA、插入 PDF、移动页面、保存当前顺序、另存为、分页保存、指定页保存及页码范围解析。所有操作返回明确成功/失败/取消结果和 UTF-8 错误文字；不能把入队、目标值相等或返回路径当作实际完成。

Core 内部优先复用 PdfEngine::PdfDocument、PdfEngine::PdfEngine 和 PdfEnginePageRef。必要的临时保存路径、文件名和目录处理使用 CSystem/CStringManager 等跨平台库，不能把 PathFindFileNameW、SHBrowseForFolderW 等 Win32 API带入 Core。Core 不维护 Qt 事件循环，也不创建 Qt 或平台线程。

四、界面迁移边界

Qt 主窗口保持旧功能关系：顶部操作区，下面为左缩略图区和右正文区；无文档时显示打开引导；缩略图与正文分别滚动和缩放；缩略图拖拽改变 Core 页面顺序；右键菜单根据页面或空白区域提供插入、分页保存和指定页保存；密码、错误和帮助使用 Qt 对话框。界面绘制可以使用 Qt 等价控件和布局，功能入口、状态转换、范围、取消和错误语义必须与需求文档一致。

五、构建和依赖

PdfReaderCore version_debug.sh/version_release.sh 继续编译 Core 本体。PdfReader 和 PdfReaderTest 的 version 脚本改为准备 PdfReaderCore 及其传递依赖，调用参数使用当前工程的 64 位 Release 动态库组合，并以 only/same 区分已由依赖链覆盖的库，避免同一库重复编译：PdfEngine same（含 CStringManager、CSystem 和 PDFium 准备）→ ReadWriteMutex same → IntDateTime only → LogManager only → CTaskThreadManager same（含 Semaphore）→ LockFreeQueue same → PdfReaderCore only。version 脚本不设置 set -e，按顺序执行各依赖构建命令。Qt 工程链接 PdfReaderCore 动态库及 Qt 依赖；Core 工程不得链接 Qt。
LockFreeQueue 只作为头文件和 inl 的构建依赖，按仓库规范不进入 PdfReader 或 PdfReaderTest 的发布目录；发布目录只保留实际运行需要的二进制。

正式入口、CMake 参数、工程登记、动态库和符号身份按仓库使用说明执行。共享 include/lib 输出可能互相覆盖时保持串行；构建返回成功、旧文件存在或时间戳变化均不能单独证明产物正确。

六、风险和验证重点

主要风险是旧 Win32 自绘交互在 Qt 中的等价实现、页面顺序与来源文档生命周期、密码错误和保存失败清理、不同平台路径/编码、PDFium 动态库组合以及 Core API 的跨语言和跨平台边界。开发期先验证 Core 最小完整链路，再验证 Qt 调用链和组合交互；正式测试按 C6 确认的环境、配置和范围执行。未能提供目标平台真实证据时，只记录为未验证，不以 Windows 通过推断五端通过。

八、本次配置与职责拆分

Qt 源码位于 src/PdfReader/PdfReader，VS 过滤器按 Configuration、UI、Bridge 等功能分组：
Config：QApplication之后显式取得Config::instance()，Config.h定义g_config宏，public m_成员直接访问；默认值在.cpp初始化列表，关联的Core和日志默认值在构造调用的init()中设置。默认布局 1180x780，最小 860x560，侧栏初始 210、最小 150；正文倍率默认 1、范围 0.25..4、步长 0.05，缩略背景倍率 0.5..2、步长 0.1。默认页图宽 112；长按 1000ms，边缘滚动周期 16ms。参数边界在 validate 检查，invalid_argument 表示调用者配置错误。
PdfReader：窗口和命令编排；不持有引擎或实现页序算法。
PdfReaderThumbnailList：单列条目、选择、长按拖动、边缘滚动与取消；独立 moc。
PdfReaderThumbnailDelegate：固定页图、居中、灰背景、文字及选择绘制。
PdfReaderCoreBridge：唯一 Core C 入口、句柄生命周期、UTF-8/Qt 类型转换、QImage 分配前限制像素数。
PdfReaderIconHelper：问号图标与程序资源图标；矢量绘制坐标为图形数据，不作为业务配置。
PdfReaderFileHelper：输出 PDF 后缀规范化；空路径仍代表取消。

Core 源码位于 src/PdfReaderCore/PdfReaderCore/src：
PdfReaderCore：每个实例独立维护文档、来源页面、工作页序和引擎。
PdfReaderCoreConfig：默认 maxRenderPixels=64000000（支持 1..268435456），exportNumberWidth=3（支持 1..9）；限制渲染资源、指定导出序号最少位数，不截断大页码。
PdfReaderCoreExportHelper：无状态的文件名与临时写入/原子替换；失败保留恢复文件。
PdfReaderCoreModels：页面来源记录；PdfReaderCoreCContext：每个 C 句柄拥有独立 C++ Core 与错误/结果缓存；PdfReaderCoreC：边界参数和异常转换；PdfReaderCoreCResultHelper：错误分类与调用结果记录。
Core同一个句柄要求串行使用；桌面通过PdfReaderTaskManager的唯一执行者访问所有Core会话，不在GUI执行PDF操作。Core本身仍同步、无Qt、无线程单例。

唯一公开包含文件仍是 PdfReaderCore/PdfReaderCoreAPI.h。C++ 示例：
  PdfReaderCoreConfig config;
  config.m_maxRenderPixels = 16000000;
  config.m_exportNumberWidth = 4;
  PdfReaderCore reader;
  reader.init(config, &error);
C/Qt 示例（首次 include 前定义 PDFREADERCORE_USE_C_API）：
  PdfReaderCoreCConfig config;
  pdfReaderCoreDefaultConfig(&config);
  config.maxRenderPixels = 16000000;
  PdfReaderCoreHandle reader = pdfReaderCoreCreate();
  pdfReaderCoreInitWithConfig(reader, &config);
必须检查结果码，并最终 pdfReaderCoreDestroy。默认 init 保持原接口兼容。显式配置 init 在已初始化时拒绝，防止无提示更改资源限制。init 失败不进入可打开状态，配置复制后修改调用方变量不改变实例。
Qt在QApplication创建后显式调用Config::instance()，通过g_config.m_core和g_config.m_windowSize等设置启动参数，再创建PdfReader window。应用Config仅GUI线程读取/修改；工作线程需要的Core配置及错误文案在会话构造时复制，不跨线程访问可变g_config。公共Core继续使用独立PdfReaderCoreConfig值对象，C++字段带m_前缀，纯C配置字段保留既有名称和布局。

所有 std::min/std::max 使用括号避免 Windows 宏。构建时生成的 VS2013 RC 文件为 ASCII，无 UTF-8 BOM（编译器限制）；C++ 文件为 UTF-8 BOM/CRLF。
