Used only by LumaPlayerCore for native microphone enumeration, capture and duplex monitoring. The implementation is compiled once in KaraokeMiniaudio.cpp, using the same compiler, architecture and CRT as Core. No separate prebuilt binary is required.
The dependency is copied by before_LumaPlayerCore.sh. App does not include miniaudio or own its device callback. miniaudio's internal device threads are third-party backend implementation; business workers remain CTaskThreadManager tasks.
Windows uses WASAPI by default; other platform backends are selected by upstream. Windows x64 validation does not establish Linux/macOS device compatibility.
Local patch: MA_WASAPI_USE_RAW_MODE, enabled only in KaraokeMiniaudio.cpp, requests RAW client properties before native format negotiation to bypass optional APO effects for microphone monitoring. Unsupported RAW properties fall back to ordinary client properties; the initialization result is logged. This changes no global endpoint settings and does not bypass mandatory hardware/driver processing. See https://learn.microsoft.com/en-us/windows/win32/api/audioclient/ne-audioclient-audclnt_streamoptions .
Timing observer: MA_WASAPI_CAPTURE_PACKET_OBSERVER is enabled only in KaraokeMiniaudio.cpp. GetBuffer returns the first captured frame timestamp in 100 ns QPC units; packets with timestamp errors are ignored. Core records packet age and output padding using atomic diagnostics; the recording worker logs them periodically. This adds no queue, wait, PCM discard or audio processing window and does not measure hardware/acoustic round-trip delay. Reference: https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer .
